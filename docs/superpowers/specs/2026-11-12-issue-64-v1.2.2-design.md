# QuotaShift v1.2.2 — Issue #64 specification and design
Date: 2026-11-12
Source: https://github.com/the-long-ride/QuotaShift/issues/64
Base: `main` at `940231193e7156fe319e2301954847aaa618b163`

## Intent and constraints
Improve visibility and account switching across Antigravity, Codex and Claude Code without altering existing credentials or session state unless the user explicitly applies an account. Preserve current provider-specific quotas and the 1–3-account monitoring limit. Use existing React/TypeScript, Rust/Tauri and persisted settings architecture. No new dependencies or automatic release workflow.

## Scope, acceptance criteria, and priority
1. **Reverse quota percentages — UI**: a persistent, default-OFF setting makes account-card quota numbers and bars show *used* (100 minus remaining); default remains *remaining*. Unknown quota stays unknown. Reset timestamps, underlying API values, and remaining-quota warning levels do not change. Display the semantic label in a tooltip.
2. **Local agent host API — follow-up (security-sensitive)**: a loopback-only, disabled-by-default service exposes redacted usage and account identifiers and supports explicit account rotation with a capability token. No secrets or refresh tokens in responses; reject requests without valid auth, remote origins and CSRF-like browser requests; enumerate providers, failure semantics, audit trail and process lifetime before implementation. Do not reuse the unauthenticated Codex router port.
3. **Antigravity 2.0 restart — follow-up (OS integration)**: restart the exact authenticated application process and verify the replacement is running. Never terminate unrelated Antigravity processes; cover Windows/macOS/Linux and restart-failure recovery.
4. **Codex desktop vs CLI — follow-up (process lifecycle)**: distinguish ChatGPT desktop from Codex CLI in process discovery and restart flow. Restart only the process classes actually running; CLI resume should use `codex resume --last` without a known conversation ID, otherwise `codex resume <id>`. Keep terminal state and existing safe restore semantics; unit-test ambiguous executable paths.
5. **Multi-account pulse — UI**: every member of the persisted tracked list has an indicator, even if the primary monitored account belongs to a different provider. A fallback indicator appears only for the primary provider/account.
6. **Card borders — UI**: draw a discernible, theme-aware 1px border on every account card at rest, preserving the stronger monitored/dragging/focused styles.
7. **Auto-monitor on Apply — UI**: add a persisted default-OFF behavior setting. After *successful* Antigravity/Codex Apply, promote the selected account into the monitored list, respecting single/multiple tracking semantics. Canceled/failed Apply must never change monitoring.
8. **Claude reset count stable — UI**: remove the Experimental tag while preserving the existing warning about the unofficial endpoint.
9. **Antigravity OAuth scopes — follow-up (authentication)**: update the sign-in flow to request and validate the new minimum permissions; correctly handle denial, consent renewal, backward-compatible reauthorization, and keep secrets out of logs. Confirm requested scopes against official provider documentation before shipping.
10. **Tier badge filtering — UI**: each provider tab's tier badges act as accessible toggle buttons. Click a tier to filter account cards and visibly select it; click it again to clear; clicking a different tier replaces the filter. Search and tier filters compose; badge counts represent query-matched accounts *before* the tier filter; filtered drag-reordering must not silently overwrite the full account order.
11. **Claude reset ON/OFF — UI**: OFF prevents both scheduled and manual unofficial reset-count fetches, hides reset-count widgets from cards/overlay/taskbar, clears stale display data, and avoids generating more polling timers; ON resumes polling immediately at the existing 30-minute cadence.

## Design alternatives and decision
- **New global store**: centralizes UI preferences but adds migrations and dependencies; rejected as disproportionate.
- **Existing localStorage + event hooks (chosen)**: reuse persistent preference/event patterns and provider components; narrowly scoped and backwards compatible.
- **Rebuild provider tabs**: might reduce repetition but risks existing model-routing, drag/drop and quota contracts; rejected.

## UI architecture
- A shared `AccountTierSummary` accepts selected tier and an optional on-toggle callback; each tab owns its selected state and provider-aware classification. Reorder is disabled while a tier filter is active.
- Quota-percent preference is a shared pure conversion utility with a subscribed React hook. The existing remaining-percent values stay authoritative.
- Auto-monitor is implemented after the switching operation reports success via the existing tracked-account identity/list facade. No account secrets are exposed.
- Claude reset fetching is gated at the hook boundary, not just in overlay rendering; cards get no count when disabled.
- CSS uses existing variables and preserves stronger state selectors.

## Security and migration
All new booleans default false when absent; existing settings/data remain untouched. The local agent API and OAuth scope changes are intentionally **not shipped** without explicit security design and platform verification. No credentials, token values, or personal account data appear in tests or docs.

## Testing / release gates
Test toggles and pure preference behavior; provider-tier filtering/search composition; monitored indicators with a non-primary provider; reset-fetch OFF/ON; dark/light border contracts; successful vs failed Apply path. Run `pnpm run prettier:check`, `pnpm run lint:loc`, `pnpm test`, `pnpm build`, `cargo test --manifest-path src-tauri/Cargo.toml`, `cargo check --manifest-path src-tauri/Cargo.toml` where supported. Run GitHub Actions once by opening a PR after all commits; use failed-job rerun only when no code change is needed.

## Non-goals for this branch
No unattended HTTP account rotation or new OAuth permissions; no speculative process killing/restarting changes; no updates to `main`, deployment or release. Implement these remaining issue items in separately security-reviewed work after their contracts can be verified.

## User-requested amendments — 2026-11-12

1. The quota option must be a two-way segmented control labeled exactly **How to show quota usage: Remaining / Used**, with the provided percent SVG. Apply consistently to dashboard cards, overlay and taskbar, including taskbar tooltip. Colors remain based on remaining.
2. Auto-monitor must be **add only**, never replace other monitored accounts. Respect the three-account limit; default OFF. A separate default-OFF setting optionally untracks existing accounts of the **same** provider. Auto-monitor enables multi-track instead of silently replacing a single primary.
3. Untrack All gets a configurable in-app shortcut, default Ctrl/Cmd+Shift+U, and uses existing confirmation.
4. Reauthentication and duplicate Add Account must preserve the saved ID, label and order; no refreshing of credentials may silently reorder accounts.
5. Codex Desktop / CLI detection must be mutually distinguishable. Windows kill by matched process PID, not image name; CLI restores via `codex resume --last` if ID unknown and `codex resume <id>` if known.
6. Antigravity 2.0 restart must target the app and verify relaunch; do not kill unrelated language servers.
7. Update all package, Cargo, Tauri and lockfile versions to v1.2.2; synchronize as-built docs and changelog. No tag or release is authorized.
8. **Unresolved security/provider contracts:** an HTTP host agent API needs opt-in, token auth, loopback-only network surface and authorized account switching. The provider's unpublished OAuth scope requirements cannot be guessed. Claude's `cedar_ember` block may be excluded from the CLI OAuth surface despite valid desktop resets. These issues require verified provider-specific integration before declaring fixed.

## Implementation review gates

- Check missing and zero percent behavior, meter severity, storage event propagation and three monitored cards including same-provider suboption.
- Do not assert `switchResult.success` on native Antigravity results: Rust returns `Result<AntigravitySwitchResult, String>` with no `success` member; reaching the continuation means IPC succeeded.
- Verify Codex process fixture cases for Windows command paths, actual CLI, ChatGPT Desktop and IDE extension; do not terminate unrelated processes.
- Run lint/LOC, tests, coverage, TS/Vite build and Rust matrix in draft PR. Keep `main` unchanged; batch pushes to reduce CI triggers.

## Follow-up — explicit vs automatic AI-agent rotation
The agent may request `{"mode":"auto","provider":"codex","poolId":"default"}` to trigger the active CLI-pool policy, OR `{"mode":"account","provider":"antigravity","accountId":"ag-123"}` to choose a specific eligible account. Both require the same agent API permission, active/enabled pool, provider match, eligibility, concurrency lock, and effective-identity verification. The request policy is test-covered in Rust but the authenticated HTTP server and rotation execution are not implemented yet.
