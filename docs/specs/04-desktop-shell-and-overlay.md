# 04 — Desktop Shell and Overlay

**Audience:** engineers & AI agents · **Verified against:** `1.3.0` · **Date:** 2026-11-16

## Main dashboard shell

- Borderless transparent Tauri `main` window (`decorations: false`, `shadow: true`, `transparent: true`): default `960×700`, minimum `912×520`. On Windows, DWM attributes clear the native window border (`DWMWA_BORDER_COLOR` → `DWMWA_COLOR_NONE`) and request rounded corners (`DWMWA_WINDOW_CORNER_PREFERENCE` → `DWMWCP_ROUND`).
- System tray icon hover tooltip: `QuotaShift // the-long-ride` (configured in `src-tauri/src/lib.rs` and maintained in `src-tauri/src/window/window_manager.rs`). Note: `src-tauri/src/window/tray_tooltip.rs` exposes `format_tooltip_with_monitored` (which omits account identity), though `window_manager.rs` currently discards its formatted result and preserves the static `QuotaShift // the-long-ride` tooltip.
- Tray menu items: `Open QuotaShift window`, `Open DevTools (Debug)`, `Open Logs Folder`, and `Quit`. Closing the main window (`CloseRequested`) calls `prevent_close()` and hides to tray (`hide_main_window`), while `RunEvent::Exit` calls `restore_router_config_on_exit`.
- Custom title bar (`Header.tsx`, `38px` height) orders right-hand controls as: conditional Update button (when `updateAvailable`), `UntrackAllButton`, Refresh button, Settings gear, `BackgroundStatusButton`, `QuitButton`, `.window-controls-divider`, and `WindowControls` (minimize, maximize/restore toggling `data-window-maximized` on `<html>`, close-to-tray via `win.hide()`). Eight directional `WindowResizeHandles` call `win.startResizeDragging(direction)` while not maximized.
- Clicking `BackgroundStatusButton` (`#background-status-btn`, featuring two stacked indicator dots `bg-status-dot--routing` and `bg-status-dot--agent` polled every `3000ms` via `useBackgroundServicesStatus`) opens `BackgroundStatusModal` (`dialog-overlay` + `dialog-box agent-api-modal bg-status-modal`), surfacing `Running`/`Stopped` state, quick enable/disable `CommonSwitch` toggles (prompting `CustomDialog` `"Stop Router Server"` or `"Disable Agent API?"` before disabling), `Configure` entry points, and metrics for **Model Routing** (`Port` copying `http://127.0.0.1:<port>`, `Enabled pools`, `Routed requests`, `In-flight`, `Last routed model`) and **Agent API** (`Port` copying `http://localhost:<port>`, default port `45692`, `Access mode`, `API key`, `Status`, plus `agentError`).
- `useHeaderWindowActions`: pointer down on a non-interactive title-bar region initiates `win.startDragging()`, and double-clicking (with a `300ms` debounce) toggles `win.toggleMaximize()`.
- `QuitButton` listens to `"quotashift-request-quit"` and opens `CustomDialog` (`"Quit QuotaShift"`) rather than terminating immediately; confirming invokes `quit_app`, which stops the Codex router listener and Antigravity workers before `app.exit(0)`.

### Search and shortcut discoverability

- Search is controlled by the application and can be focused by the configured in-app `focusSearch` shortcut; pressing `Escape` in the search field clears the query.
- The search placeholder renders `Search accounts... (${formatShortcutDisplay(shortcuts.focusSearch)})`.
- `useInAppShortcuts` installs a capture-phase `keydown` listener (ignoring `event.repeat` and `[data-shortcut-recording="true"]`) supporting `addAccount`, `toggleTheme`, `toggleCardView`, `focusSearch`, `refreshAll`, `openSettings`, `quitApp`, `untrackAll`, `zoomIn`, `zoomOut`, and `zoomReset`.
- Buttons with in-app shortcuts expose the current binding through the shared custom tooltip, rendering bindings as individual keycaps.
- The Settings header theme control retains its state-aware sun/moon icon; the combined light/dark artwork is limited to the Keyboard Shortcuts settings row.

### Native WebView zoom and auxiliary zoom compensation

- `useMainWindowZoom` persists percentage in `quotashift_main_webview_zoom_v1` (`70%–190%`, step `10%`, default `100%`) and calls `getCurrentWebview().setZoom(next / 100)`.
- Driven by `"quotashift:zoom"` (`-1 | 0 | 1` from `zoomIn`/`zoomOut`/`zoomReset` shortcuts) and RAF-throttled `Ctrl+wheel` input.
- Because Tauri/WebView2 shares page zoom across windows of the same origin, `useNativeZoomCompensation` reads `win.scaleFactor()` in auxiliary windows (`TaskbarApp`, `OverlayTooltipApp`), computes `zoomCompensation(window.devicePixelRatio, nativeScale)`, writes `--native-zoom`, and toggles `body.native-zoom-fix` so taskbar and tooltip surfaces stay cleanly scaled against monitor DPI rather than inheriting main-window zoom.

## Dialog, account, and toast geometry

All shared `.dialog-overlay` surfaces (`src/styles/shared/modals.css`) reserve the native title-bar region:

- Overlay starts at `top: 38px` and spans `height: calc(100% - 38px)` with `z-index: 9999`.
- `.dialog-box` sets `width: 350px`, `max-width: calc(100vw - 32px)`, `min-height: min(140px, calc(100vh - 62px))`, `max-height: calc(100vh - 62px)`, and `overflow-x: hidden; overflow-y: auto` so overflow scrolls inside the dialog instead of spilling outside the window under high zoom.
- `.dialog-box--account` uses `min-height: auto; height: auto; max-height: calc(100vh - 62px); overflow: hidden; text-align: left;` paired with `AccountModalLayout` and shared account primitives (`AccountCaptureLabelField`, `AccountCredentialsSection`, `AccountTierSummary`, `QuotaDisplayRow`, `AccountResetCount`, `ReauthAccountBanner`, `ReauthenticateAccountButton`, `AccountSortMenu`).
- While a dialog is open, `body:has(.dialog-overlay) .app-header` raises `.app-header` to `z-index: 10000` with a drop shadow for visual separation.
- `CustomDialog` attaches a capture-phase `keydown` listener mapping `Escape` to cancel (`onClose(false)`) and `Enter` to confirm (`onClose(true)`). `useCloseOnEscape` provides shared Escape dismissal for modals such as `BackgroundStatusModal`.
- `PassphraseModal` handles `create | unlock | export | import | migrate` vault passphrase flows (minimum length 4 plus confirmation match for `create`/`export`, `Escape` cancels, `Enter` submits).
- `ResetCreditsDialog` renders a shared `role="dialog" aria-modal="true"` modal listing remaining Claude/Codex reset credit grants (`Unknown` when `count === null`, `${count} Available`, each grant's `Expiry` and optional `Granted` timestamp, and a header `×` close button).
- `ExperimentalTag` renders `.settings-experimental-tag` (`Experimental`) only where explicitly designated; `Show Claude reset count` does not carry an experimental tag.
- `Toast` (`src/components/common/Toast.tsx`) renders `.app-toast.app-toast--${kind}` (`info | success | warning | error`) with `role="status"`, `aria-live="assertive"` for errors (`"polite"` otherwise), configurable `durationMs` auto-dismiss, and a manual close button.

## Windows taskbar strip

- `src-tauri/src/window/taskbar_dock.rs` docks the frameless `taskbar` window (`index.html?window=taskbar`, initial `200×40`, `focus: false`, `skipTaskbar: true`, `alwaysOnTop: true`) to `Shell_TrayWnd` via `GWLP_HWNDPARENT` (`dock_to_taskbar`), inset 2px (`round(2.0 * scale)`) before `TrayNotifyWnd` on `bottom`/`top` taskbars or stacked above `TrayNotifyWnd` on vertical `left`/`right` taskbars.
- A background watcher (`spawn_watcher`) re-runs `place_strip` every **250ms**, hiding the strip when `taskbar_geometry()` is unavailable, taskbar `auto_hide` is enabled, or `is_fullscreen_foreground` detects a non-shell fullscreen window (ignoring Windows shell windows unless `ForceStartSize == 2` or `TabletMode == 1` in HKCU).
- Content dimensions reported through `set_taskbar_content_size` (`DEFAULT_CONTENT = (120.0, 36.0)`) are rounded upward (`(v * scale).ceil() as i32`) so fractional DPI scaling never clips the last pixel of text; `TaskbarApp` adds `4px` along the scroll axis to its measured size.
- Edge changes emit `"taskbar-edge-changed"` (`bottom | top | left | right`), queryable via `get_taskbar_edge`. `assert_topmost` checks `WS_EX_TOPMOST` and `is_above_window` (`should_raise_strip`) before raising with `HWND_TOPMOST | SWP_NOACTIVATE`, keeping Z-order separate from the main overlay window and avoiding covering existing tray menus.

## Desktop overlay

QuotaShift runs two frameless transparent helper windows alongside `main`: `overlay` (initial `340×80` in `tauri.conf.json` and `setup.rs`, anchored primary bottom-right with `20*scale` margin and `50*scale` taskbar offset) and `overlay-tooltip` (initial `340×38` in `tauri.conf.json`, configured with `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT` click-through via `make_window_click_through` for hover tooltips and temporarily focusable when showing a taskbar menu).

### Native base sizes and theme sync

- `OverlayWindowSizingBridge` is the sole owner of `win.setSize(new LogicalSize(...))`, measuring unzoomed CSS px via `getComputedStyle`, sizing via `resolveMeasuredOverlaySize` and `resolveViewportAdjustedOverlaySize` (growth capped at 2× base dimensions), and clamping to the monitor work area (`clampToWorkArea`).
- Base dimensions (`src/utils/common/ui/ui-adjustment.ts`): Antigravity `340×80`, Codex/Claude compact overlays `220×68`.
- `Header.tsx` broadcasts `ui-adjustment-changed` and `app-theme-changed` (`emitTo`) to `"overlay"`, `"overlay-tooltip"`, and `"taskbar"`. Whole-surface scale ranges `80%–200%` (default `100%`, `quotashift_ui_adjustment_v1`); overlay themes are `glassmorphism` and `mono` (legacy `black-white` normalizes to `mono`).
- Text tooltips placed by `placeTextTooltip` (`overlay-tooltip-placement.ts`) target `TEXT_TOOLTIP_WIDTH = 480` (capped by `maxWidth` when provided) × `TEXT_TOOLTIP_HEIGHT = 38`, adding `8px` vertical wrap padding (`WRAP_PADDING`) when content wraps across lines.

### Tracked tray/overlay state and quota presentation

- Only tracked accounts publish to the overlay/taskbar state; tray and overlay payloads omit account email/label identity where stripped, and background polling of untracked accounts must not overwrite tracked state.
- Claude/Codex expose recognized limit bars (`5H`, `WK`, and `MO` where present) colored by remaining quota severity (`<10%` `#ef4444`, `<20%` `#f97316`, otherwise default fill), while `useQuotaPercentMode` (`quotashift_show_used_quota_v1`, default **Used**) controls displayed numbers and progress bar fills without fabricating missing values as 100%.
- Antigravity preserves grouped quota rows when multiple pools are available. Gemini-only accounts render two plain `5H`/`WK` bars without model-family icons or headings using the narrower single-pool layout (`hideFamily`). Multi-family Antigravity overlays stretch pool columns uniformly (`align-items: stretch`); when 3+ rows/pools are shown (`rows.length > 2`), the row enters `.overlay-families-row--three-pools` (matching the `187px` inner width of the 2-pool layout) and renders `.overlay-progress-track` + `.overlay-progress-bar` (`20px` tracks) for all pools including Argon, hiding only Argon's `WK` text label (`hideLabel={isArgon}`) so its bar and percentage center cleanly under `GeminiFourLogo`. When the quota API omits a previously depleted Argon pool, the most recent `0%`-remaining value can remain visible until a known reset expires (historical display only, not fresh proof for rotation).
- **Claude reset count**: opt-in (**Settings > Monitoring > Show Claude reset count**, key `quotashift_claude_reset_credits_enabled_v1`, default OFF). The switch gates fetching for all real Claude accounts and controls card, overlay, and taskbar badges. When ON, an unofficial read-only `/api/oauth/usage?cedar_ember=1` source is queried with a 30-minute per-account cache; known positive counts display normally, and unavailable results produce `RC?`/`Unknown`, not a fabricated zero. Turning OFF prevents new requests and hides all optional badges.
- Hovering the Claude reset badge shows only the number of resets remaining; Codex's reset tooltip also includes nearest expiry when known.
- Hovering a card in `OverlayCardStack` or a node in `OverlayCircleStack` publishes the rich `TaskbarTooltipCard` detail panel to `overlay-tooltip` via `useCircleOverlayActions` (`handleHoverNode` / `buildTaskbarColumns` / `computeCirclePanelAnchor`, using a `280 * scale` edge threshold for vertical stacks and `180 * scale` / `160 * scale` for horizontal stacks). Live hover suppression (`isHoverSuppressedRef` reading `useOverlayDrag.isDraggingNow()` and `cardMenuOpenRef`, plus `onCloseMenu` syncing `menuState.isOpen` when clicking outside) and `activeHoverKeyRef` deduplication with `onMouseMove` restore hover immediately after left-click, drag, or context menu dismissal without requiring the pointer to leave and re-enter the window.

### Screen topology and dragging

- `useOverlayDrag` handles manual pointer dragging (`DRAG_THRESHOLD_PX = 4`, `setPosition(PhysicalPosition)`) and double-click detection (`500ms` / `6px` tolerance) to focus the dashboard tab and scroll to the card (`FOCUS_ACCOUNT_CARD_EVENT`).
- `useOverlayDataAndWindow` persists position in `quotashift_overlay_pos` (`onMoved` debounced `150ms`), checks `availableMonitors()` every `10s` and on `visibilitychange` (`visible`), and re-anchors to primary bottom-right if the overlay falls outside all connected monitors.
- On Windows, `src-tauri/src/window/overlay_clamp.rs` attaches a Win32 window subclass (`SetWindowSubclass`, id `4001`): `WM_MOVING` clamps dragging to the union bounding box of `EnumDisplayMonitors` work areas, `WM_DISPLAYCHANGE` calls `reset_overlay_to_primary_bottom_right` (`SPI_GETWORKAREA`, `16px` padding), and `WM_WINDOWPOSCHANGING` is kept as an intentional no-op.

## Display mode and multi-account tracking

The Appearance settings tab's **Monitored Display** subsection (`src/utils/common/settings/display-mode.ts`) consolidates:

- **Quota display**: `None | Card | Circle | Taskbar` (`quotashift_display_mode_v1`, normalized values `"none" | "overlay" | "circle" | "taskbar"`), defaulting to `Taskbar` on Windows (and falling back to `Overlay` on platforms where `isTaskbarSupported` is false). Legacy `quotashift_overlay_enabled` migrates (`"false"` → `none`, `"true"` → `overlay`) and stays synchronized. The quick toggle (`nextQuickToggleMode`) cycles `None → Card ("overlay") → Circle ("circle") → Taskbar (Windows only) → None`. When no accounts are tracked, `effectiveDisplayMode` resolves to `none` and attempting to enable a display triggers `buildNoTrackedAccountToastMessage`. Calling `set_display_mode` shows the `overlay` window for `"overlay"` or `"circle"`, or the Windows `taskbar` strip for `"taskbar"`.
- **Circle overlay (`OverlayCircleStack`, `OverlayCircleNode`)**: When `displayMode === "circle"`, each tracked account renders as a `58×58px` glass/mono circle node wrapping a `40×40px` `.overlay-circle-avatar-zone` (avatar image/initial/`ClaudeStackedAvatar`, `1px`-inset top corner badges for reset count and Claude `5H` guardrail, and a bottom `.overlay-circle-bottom-badges` flex container with `gap: 2px` holding `position: static` `13px` badges with `8px` provider icons for account tier, Claude `WK` guardrail, and provider icon so they never overlap) closely hugged by segmented radial quota arcs (`r = 25`; multi-pool Antigravity renders 2 parallel concentric bars per pool on Gemini left and Claude/OpenAI right — using constant horizontal `halfGapPx` so `outer` and `inner` arcs share the exact same top and bottom gap — plus Gemini 4 Argon on top when present with its exhausted `0% remaining` / `100% used` endpoint anchored on the left side; symmetric 2 `5H`/`WK` arcs on Codex/Claude/Gemini-only rising upward from bottom to meet near the 12 o'clock top at 100%; health-toned `<20%` warning / `<10%` critical) and a bottom theme-matched `4px`-radius frosted glass / mono percentage badge (`5H%/WK%`, or single `month %` on monthly plans, built by `circle-telemetry.ts`; badge outline follows only the overlay theme while value text carries warning/critical tone). Up to `useMaxMonitoredCards()` (`MAX_VIEWPORT_CARDS = 3` default) circles render in either `"vertical"` or `"horizontal"` orientation (`quotashift_circle_orientation_v1`, swapped via `CircleOrientationRow` in Settings when Card or Circle is selected or `OverlayMenuSwapOrientationItem` in the context menu), reusing `TaskbarTooltipCard` on hover and `TaskbarContextMenuView` on right-click via `overlay-tooltip` (guarded by `circleMenuOpenRef` so moving the cursor out of the circle overlay to reach the external menu does not hide it), with `22×22px` square `.overlay-nav-arrow` pagination buttons.
- **Max monitored account cards (`MaxMonitoredCardsRow`, `useMaxMonitoredCards`)**: configures how many simultaneous monitored accounts (`quotashift_max_monitored_cards_v1`, `1–20`, default `3`) render in `OverlayCardStack`, `OverlayCircleStack`, and `TaskbarApp` before scrolling/pagination kicks in; `OverlayWindowSizingBridge` passes `maxRows: MAX_MONITORED_CARDS_MAX` (`20`) to `resolveMeasuredOverlaySize` so multi-card and multi-circle windows resize cleanly.
- **Overlay & taskbar tooltip UI scale**: `80%–200%` (default `100%`).
- **Overlay theme**: segmented switch between `glassmorphism` and `mono` (normalizing `black-white` → `mono`). All segmented controls use a sliding indicator with reduced-motion fallback and uniform `font-weight: 600` to prevent width jitter.
- **Reset monitor display**: resets overlay position, scale, and theme to defaults.

### Taskbar strip rendering and hover details

- `TaskbarApp` applies `useNativeZoomCompensation` and `useTaskbarSlide` (`240ms`, `14px` enter offset, `prefers-reduced-motion` aware), renders up to the configured `useMaxMonitoredCards()` limit (`MAX_VISIBLE_TASKBAR_ACCOUNTS = 3` default, `1–20`) tracked accounts per viewport, and paginates overflow via `TaskbarNavArrow` (`left`/`right` on horizontal edges, `up`/`down` on vertical edges) and mouse wheel.
- Theme & layout: `useTaskbarWindowSync` syncs both `glassmorphism` and `mono` overlay themes (`data-overlay-theme`) alongside app `light`/`dark` (`data-theme`) and taskbar edge (`get_taskbar_edge` / `"taskbar-edge-changed"`). `TaskbarApp` resolves popup/menu panel anchors via `computeTaskbarPanelAnchor` using both client rects and native `win.outerSize()` so top/bottom and left/right taskbar gaps remain symmetric.
- `TaskbarColumn` (and `OverlayCard`) render the account avatar (image, initial, pure `ClaudeLogo` for the alias-less local session, or background `ClaudeLogo` + foreground alias initial letter for Claude accounts) with overlay badges (tier, reset count, provider) and up to two metric rows (`5H`/`WK` or `MO` for Codex/Claude; Gemini and Claude/OpenAI rows formatted `5H%/WK%` horizontally, or centered icon-free `%`-free `5H/WK` on vertical `left`/`right` Antigravity taskbars, plus a dedicated `.taskbar-argon-divider` + `.taskbar-argon-col` displaying `gemini-4` and `WK` percentage horizontally or centered plain numeric `WK` without icon/`%` vertically; separate plain `5H`/`WK` lines without family icons on Gemini-only). Vertical glass cards raise backdrop opacity (`rgba(12, 15, 20, 0.84)`) so underlying pinned taskbar icons do not bleed through quota values. Item side padding accommodates the `4px` badge overhang, and `margin-left: auto` right-aligns the strip without left clipping.
- Hovering publishes `TaskbarTooltipDetails` to `overlay-tooltip` (`TaskbarTooltipCard`), rendering account identity, tier, reset count, and per-family/window meters + resets formatted via `formatCardResetLabel` (using the Gemini 4-point star + `"Argon"` label when Argon is present). Hover sequence guards (`hoverSeqRef` in `TaskbarApp`, `eventSeqRef` in `OverlayTooltipApp`, `isCurrent()` checks inside `placeTaskbarTooltip`, plus `TASKBAR_TOOLTIP_LEAVE_GRACE_MS = 150` and `TASKBAR_TOOLTIP_EXIT_MS = 120`) ensure a stale async hover never re-opens after the pointer leaves.

### Context menus and interactivity

- **Taskbar & Circle context menu (`TaskbarContextMenuView`)**: left-click or right-click on any `TaskbarColumn` (or right-click on an `OverlayCircleNode`, which sets `data-circle-menu="true"` on `.taskbar-menu-root` for larger `28×28px` `.overlay-menu-item` targets and `16×16px` icons) opens the menu via `placeTaskbarMenu` (temporarily making `overlay-tooltip` focusable and focusing it; `tooltipHeadroom = 28`, `padX = 72`, `nearEdgePad = 4` on `left`/`right` placements so the bar hugs the target side while edge tooltips shift inward, `data-placement="below"` docking the bar at the top edge with tooltips flipped below, `gapPx = 4`). Actions: `Refresh usage` (`request-refresh-usage`), `Open dashboard` (`show_dashboard` + `FOCUS_ACCOUNT_CARD_EVENT`), light/dark theme toggle, optional `Apply this account` (`OverlayMenuApplyItem`, shown for Antigravity/Codex when `accountId` is present; no confirmation dialog), optional `Swap vertical / horizontal` (`OverlayMenuSwapOrientationItem` in Circle mode), `Untrack this account` (`request-untrack-account`), and `Hide overlay`/`Hide display` (`saveDisplayMode("none")` + `set_display_mode("none")`). Dismissed via Windows low-level mouse hook polling (`start_taskbar_menu_dismiss` / `stop_taskbar_menu_dismiss` at `30ms` → `"taskbar-menu-dismiss"`), blur, `Escape`, or `5000ms` unhovered idle timer.
- **Overlay context menu (`OverlayContextMenu` / `useOverlayContextMenu`)**: right-clicking an overlay card exposes the same action set in an icon-only horizontal bar (`max-width: none` on `.overlay-context-menu` so all 7 buttons — `Apply this account`, `Refresh usage`, `Open dashboard`, `Switch to light/dark mode`, `Swap vertical / horizontal` via `OverlayMenuSwapOrientationItem` / `onSwapOrientation`, `Untrack this account`, and `Hide overlay`/`Hide display` — fit without clipping or wrapping, with `extraButtonsWidth` clamping in `useOverlayContextMenu`). *(Note: `useOverlayContextMenu.handleHideOverlay` hides via `quotashift_overlay_enabled = "false"`, `overlay-visibility-changed`, and `set_overlay_visible(false)` rather than `saveDisplayMode("none")` + `set_display_mode("none")`.)*

### Multiple tracked accounts and pagination

- One switch (`"Track multiple accounts"`, `quotashift_multi_track_v2`, default ON, migrated from v1 per-provider flags) lets users track accounts across providers in one ordered, deduplicated list (`quotashift_overlay_tracked_v2` of `{ provider, id }` entries, migrated from v1 keys; `toggleTrackedEntry` adds/removes without enforcing a hard cap when multi-track is enabled, though `MAX_TRACKED = 3` remains exported as a legacy constant; turning multi-track off runs `trimTrackedList` to keep only the primary account).
- **Vertical/horizontal stack and pagination**: `OverlayCardStack` (`ui-adjustment.css` `.overlay-cards--horizontal`, `24×24px` square `.overlay-nav-arrow` pagination buttons with `position: static; align-self: center;`, `overlay-measure.ts` `cols`, `OverlayWindowSizingBridge.tsx`) and `OverlayCircleStack` share `CIRCLE_ORIENTATION_KEY` / `CIRCLE_ORIENTATION_EVENT` to support both Vertical (centered top/bottom `up`/`down` arrows) and Horizontal (centered inline `left`/`right` arrows) layouts, displaying up to `useMaxMonitoredCards()` accounts (`MAX_VIEWPORT_CARDS = 3` default, configurable `1–20`) and paginating overflow via `OverlayNavArrow` and `160ms`-throttled wheel events (`delta >= 8`). `TaskbarApp` similarly paginates beyond `useMaxMonitoredCards()` (`MAX_VISIBLE_TASKBAR_ACCOUNTS = 3` default, `1–20`).
- **Untrack all button**: shown in `Header` whenever `loadMultiTrackEnabled() && loadTrackedList().length > 0`; responds to `"quotashift:untrack-all-request"` and opens `CustomDialog` `"Untrack All Accounts"` to invoke `clearTrackedAccounts()` + `clearMonitoredOverlayState()`.
- **Tracking started toast**: `buildTrackStartedToastMessage` formats a toast mentioning `Overlay or Taskbar` (Windows) or `Overlay` (other platforms) plus the active `toggleOverlay` shortcut.
- **Navigation to dashboard**: double-clicking an overlay card or taskbar column, or choosing `Open dashboard` in either context menu, calls `show_dashboard({ tab })` and dispatches `FOCUS_ACCOUNT_CARD_EVENT`, centering the card (`findAccountCardElement` → `centerElementInContainer`) and highlighting it.
